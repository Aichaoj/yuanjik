# 变更单 · 数显 v35：出生日期改为「年 / 月 / 日」三段显式选择

- 日期：2026-10-21
- 等级：**L2**（表单结构变化，涉及 2 个表单 + 2 个文件；接口契约不变）
- 提起：师父令（2026-10-21 11:52）
  > 「元神的会员注册身份时间输入，年份选择没有，只有月份加减，年月最好可以输入选择」

## 一、现象与根因

| 项 | 实况 |
|---|---|
| 涉及屏 | ① `screen-profile` 生辰建档（`#inBirthDate`）② 家庭档案新增/编辑（`#famBirthDate`） |
| 现状实现 | 均为原生 `<input type="date">`（index.html:256、899） |
| 用户所见 | 弹出的是系统原生日期控件，在部分手机 WebView / 定制 ROM 上**只给出月份加减、无法直接选年份** |
| 根因 | 控件形态由**设备端**决定，我方无法保证「年份可选」；且无任何显式的年/月输入入口 |
| 影响面 | 出生日期是建档与家庭档案的必填项 ⇒ 该类设备上**无法完成建档**，等于功能不可用 |

## 二、改法（最小结构变更，接口零改动）

1. 两个表单的出生日期，改为**三个显式下拉**：年（1900–今年）/ 月（1–12）/ 日（按年月自动算天数）。
2. 新增**隐藏域** `#inBirthDate` / `#famBirthDate`，值仍为 `YYYY-MM-DD`：
   - `validateProfile()`、`submitProfile()`、`saveFamMember()`、`openFamForm()` 的**读取路径一行不改**；
   - 提交给服务端的 `birth_local` 仍是 `YYYY-MM-DD HH:MM`，**契约不变**。
3. 联动规则：改年/月 → 日选项按当月天数重算（2 月 30 → 自动落到 28/29）；三段未齐 → 隐藏值为空，校验按原口径报「请选择出生日期。」
4. 顺带解决「只有月份」的另一半诉求：年份是**列表**，1900–今年一次可选，不需要逐月翻。
