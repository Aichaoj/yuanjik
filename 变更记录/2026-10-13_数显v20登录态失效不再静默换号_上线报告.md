## 二、根因（已定位到代码行，属真实缺陷）

`shuzi\web\app.js` 的请求层原有一段「**鉴权失效静默降级**」：

```js
// 旧代码（v12~v19）
if (AUTH_CODES[code] && !opts._retried) {        // 20000/20001/20002 = 登录态失效
  clearToken();
  return ensureToken(true)                        // ← 悄悄取一个新的游客令牌
           .then(function () { return apiFetch(path, retryOpts); });   // ← 用新身份重试
}
```

后果链：

1. 令牌失效（**TTL 只有 15 分钟**，或服务重启后内存会话丢失）→ 任意一次接口调用触发降级；
2. 前端**静默**清令牌、按 `device_id` 取游客令牌并重试 → 身份变成"这台设备的新游客账号"；
3. 界面右上角**不会提示"已退出登录"**（登录态镜像只在下次 `password/status` 时才可能更新）；
4. 用户看到的正是："手机号还在、签到变成 0/1、档案不见了"。

**副产品**：库里因此堆了多个空游客账号（无档案、个别仅 1 次打卡）——这解释了过去几次"账号像是分裂了"的现象（与 v13.1「账号改绑」同源）。

## 三、修了什么（前端单文件，语义最小改动）

| 改动 | 内容 |
|---|---|
| 新增 `authFailedNoGuest()` | ① 清本地令牌 + 清登录态镜像（`hasPassword/phoneMasked`）；② `state.sessionExpired = true`；③ 用既有全局错误条给一句话：**"登录已过期：为避免把你的记录换成另一台设备的账号，已停在登录状态。你的档案与打卡记录都在原账号里，重新登录即可看到。"**；④ 只提示一次，并自动打开登录面板 |
| 请求层 | 遇 `AUTH_CODES` 时改为**调用 `authFailedNoGuest()` 并抛出可读错误**，**删掉** `ensureToken(true)` 那句自动换号的写法 |
| `ensureToken()` | `sessionExpired` 为真时**不再自动取游客令牌**（`return false`），由既有分支给可读提示 |
| `loadAuthStatus()` | 无令牌时**一并清掉** `hasPassword/phoneMasked` —— 不再出现"看起来还登录着"的假象 |
| `boot()` | 新增 `?probe_token=<串>` **验收钩子**：写成本地令牌以复现"登录态失效"路径（仅用于真浏览器验收；令牌来自用户自己的地址栏、失效即被清掉，无跨站能力） |

**未改**：服务端一行未动；游客首访、注册/登录、找回密码、退出登录、v14 首页指数、v19 此刻时相全部照旧。

## 七、两条工具链教训（已并入技能错误记录）

1. **部署载荷必须纯 ASCII**：本轮 `_shuzi_v20.ps1` 里我写了中文断言字符串（`Contains('登录已过期')`）
   → 载荷校验直接拦下（22 个非 ASCII）。**改法**：断言改判 `\uXXXX` 转义后的形式。
   （这条不是新知识，是旧铁律的一次现场复现——所以我没让它上线。）
2. **本机用 PowerShell 编辑 `.ps1` 会带 BOM**：`Set-Content -Encoding UTF8` 写出 BOM，
   又被"纯 ASCII"校验拦下；`[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` 才是无 BOM。
