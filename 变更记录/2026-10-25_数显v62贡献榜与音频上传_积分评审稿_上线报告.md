## ② 后台上传音频（绕开 >2 MB 单请求限制）

三个接口（都要后台令牌，沿用 `/v1/admin/login`）：

| 接口 | 作用 |
|---|---|
| `POST /v1/admin/music/upload/begin {filename,size}` | 建会话；校验扩展名（ogg/mp3/m4a/wav/aac）与大小（≤20 MB） |
| `POST /v1/admin/music/upload/chunk {upload_id,seq,data_b64}` | 单片解码后 ≤2 MB（base64 ≈2.7 MB，低于反代阈值） |
| `POST /v1/admin/music/upload/finish {upload_id}` | 按序拼片 → 校验声明大小 → 计算 SHA256 → 落 `web/music/u<时间>_<sha前10>.<ext>` → 清理临时目录 |

- 后台页 `/admin/music.html` 新增「选文件 → 上传」：进度条、逐片进度、完成后自动把 `music/xxx.ogg` 填进表单；
- **安全**：文件名只取扩展名、落盘名由服务端生成（不用用户文件名）；分片大小/总大小双限；上传会话 id 只允许 16 位十六进制。

## 未验证 / 风险

1. **线上没有真跑一次上传**（只在本地跑了 3.12 MB 分片全流程）——避免在生产 `web/music/` 留测试文件；建议首次真实上传由师父在后台点一次，我在旁边看回执。
2. 上传**不校验音频内容**（只查扩展名与大小）；如果要防伪装文件，需要引入 ffprobe 或魔数校验。
3. 榜单**没有做分页/赛季**（只看前 N 与我的名次）；若参与人多，需要"赛季 + 重置"规则（但流水永存不变）。
4. 上传会话**没有过期清理**（未 finish 的临时目录会留着）；量大时需要定时清理任务。
5. 积分兑换仍是**文档**，一行代码都没动（保持"只展示、不发放"）。

## 教训

- 评审稿先写"红线"再写"玩法"：这类激励功能最容易越界到资金/赌博/健康承诺，先把不能做的写死，能做的自然清楚。
- 分片上传要**两个限制都拦**（单片 + 总量），只拦一个就等着被打。
