## 一、要做什么（一句话）

在 AI数显用户区新增「**添加家人**」与「**家庭健康档案**」：用户把家人的称呼/关系/出生信息录进来，就能**在一屏里看到全家人的今日指数与分档**，并对某位家人发一条**关怀提醒**。

## 二、口径边界（**动手前先钉死，不许发挥**）

| # | 口径 | 说明 |
|---|---|---|
| 1 | **家人的指数＝与「我」完全同一条链路** | 内核 `phase_index.phase_index(birth_local, lon, lat, target_date)` → 装配层 `display_normalize()`。**不新写第二份公式**（铁律十七②），展示分与分档必须与 `GET /api/v1/rhythm/daily` 的 `index.score` / `index.band` 同源可复算 |
| 2 | **观察等级对家人恒为 `null`** | 家人不是本平台用户、没有观测史，基线必然未建立。**不得**输出 L0–L4，页面只显示「基线建立中 n/7」（专利 2 权利要求 6；内核 `offset_layer` 的行为一个字不改） |
| 3 | **分档沿用内核 `band_of`（阈值 85/70/55）** | A/B/C/D 是**时相分档**，**不是**观察等级，两者不可互换、不可混排 |
| 4 | **家人数据只属于录入者** | 家人不是账号、没有 member_id。`family_member` 以「录入者 member_id」为属主；任何他人（含好友）都不可见、不可枚举 |
| 5 | **不得进社交面** | 家人昵称/生辰**不得**出现在 `friends` / `feed` / `ranking` / 邀请预览 的任何响应里（有断言） |
| 6 | **不做诊断、不做医疗表述** | 与全站一致：免责声明随响应返回；文案只写「指数/分档/关怀提醒」，不写病名、不写诊断 |
| 7 | **上限 8 位家人**（家庭席位） | 超出返回可读错误；这是产品口径，不是技术限制 |

## 三、接口契约（新增，全部挂在 `/api/v1` 前缀下，与既有接口同风格）

| # | 方法 + 路径 | 说明 |
|---|---|---|
| 1 | `GET /api/v1/family` | 家庭成员列表 + 家庭汇总。未登录 → 401 |
| 2 | `POST /api/v1/family/members` | 添加家人 |
| 3 | `POST /api/v1/family/members/update` | 修改家人（body 带 `family_id`；**不新造第二套路径风格**） |
| 4 | `DELETE /api/v1/family/members/{family_id}` | 删除家人（走 `handle_dynamic`，先例同 `social.handle_delete`） |
| 5 | `POST /api/v1/family/remind` | 对某位家人发一条关怀提醒 |
| 6 | `GET /api/v1/family/reminders` | 我发出的关怀提醒（最近 N 条） |

**`GET /api/v1/family` 响应形状（逐字，前端照此渲染）**
```json
{"code":0,"message":"ok","data":{
  "members":[{"family_id":"fam_xxx","nickname":"妈妈","relation":"母亲",
              "relation_code":"mother","birth_local":"1962-03-08 06:20",
              "index":{"score":74,"band":"B","band_name":"良","score_kernel":70,
                       "basis":"...","basis_note":"..."},
              "level":null,"baseline_text":"基线建立中 0/7",
              "age":63,"last_reminded_at":"2026-10-08 09:10:00"}],
  "summary":{"count":3,"avg_score":71,"attention_count":1,"attention_band":"C"},
  "disclaimer":"...","reminders":[{"family_id":"fam_xxx","nickname":"妈妈",
              "kind":"care","text":"今天记得早点休息","created_at":"..."}]
}}
```

**校验规则（全部必须有可读报错，不许静默吞）**
- `nickname`：1–12 字，去首尾空白；命中敏感词 → 拒绝（复用 `social` 的清洗口径）
- `relation_code` ∈ `self|father|mother|spouse|child|sibling|grandparent|other`（中文名由服务端映射，前端只传 code）
- `birth_local`：`YYYY-MM-DD HH:MM`，且必须是合法时间（非法 → 400）；`longitude` ∈ [-180,180]、`latitude` ∈ [-90,90]
- **同属主下「昵称+生辰」重复** → 拒绝并提示「这个家人已经添加过了」
- 超过 8 位 → 拒绝并提示「家庭席位已满（8 位）」
- `remind`：`kind` ∈ `care|checkin|birthday|custom`，`text` ≤ 60 字；**同一家人同一 kind 同一天只写一条**（幂等，重复调用返回原记录）

## 四、前端（AI数显 H5）

1. 用户区（我的/健康档案）新增入口 **「添加家人」**；已有家人时同一入口显示「家庭健康档案（n）」。
2. 新增一屏 `screen-family`：
   - 顶部家庭汇总：**全家 n 人 · 平均指数 xx · 需关注 x 人**
   - 家人卡片：昵称 / 关系 / 今日指数与分档 / **基线建立中 n/7**（等级一律不显示 L0–L4）/ 最近提醒时间 / 「关怀提醒」与「编辑」「删除」
   - 空态：一句引导 + 「添加家人」按钮
   - 添加/编辑表单：昵称、关系（下拉）、出生日期时间、城市或经纬度
3. **适屏**：430×932 与 1440×900 都要正常（不得出现横向滚动条、不得文字溢出卡片）。
4. **0 条新增 JS 错误**（控制台 error 数不得增加）。

## 五、验收标准（**可验证**，关闭前逐条自检）

| # | 验收标准 |
|---|---|
| 1 | `GET /api/v1/family` 未登录 → **401**；登录 → 200 且 `data.members` 为数组 |
| 2 | 添加家人 → 200，`GET` 能读到；**家人 index.score 与内核对该生辰直算并 `display_normalize` 的结果逐字相等**（脚本复算断言） |
| 3 | 家人的 `level` 字段**恒为 `null`**，`baseline_text` 形如「基线建立中 0/7」（断言：响应中**不出现** L0–L4 字样） |
