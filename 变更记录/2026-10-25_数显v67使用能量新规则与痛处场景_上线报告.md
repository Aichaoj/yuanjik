## 二、逐条落地

### 2.1 结构：使用能量卡放到「我的能量」上面

顺序改为：共享指数 → **使用能量** → **我的能量** → 积分 → 贡献榜 → 注入流水 → 我的统计。
「我的能量」卡：个人能量值（大数字）+ 今日使用次数 `x/2`。

### 2.2 规则：每次 ≤15 分钟、每天 2 次、共享 −1、我的 +10

| 参数 | 值 | 实现位置 |
|---|---|---|
| 单次上限 | **15 分钟** | `SESSION_MAX_MINUTES = 15`（到点由服务端收尾） |
| 每天次数 | **2 次** | `SESSION_DAILY_COUNT = 2`（第 3 次 429，文案提示明天再来） |
| 每次我的能量 | **+10** | `SESSION_ENERGY = 10`，开启即入账并 **1:1 折积分** |
| 每次共享能量 | **−1** | `SESSION_SHARED_COST = 1`，写入 `vault_usage`（只增） |
| 共享指数 | `10000 + 全体贡献 − 全体使用扣减` | `_shared()` |

> 原先「每分钟 1–10 能量、按 15 分钟一档扣共享」的机制**已被本规则取代**（同一入口只保留一种口径，避免两套并存）。

### 2.3 「舒缓不适（意念痛处）」

- 使用能量新增**场景选择**：`补充能量` / `舒缓不适（意念痛处）`；
- 选后者时出现**部位选择**（头部 / 颈肩 / 腰背 / 关节 / 腹部 / 其他），随会话存档（`vault_session.purpose/spot`）；
- **合规文案**（固定显示）：「舒缓不适是放松与注意力练习，**不是止痛治疗**；疼痛持续、加重或伴随其他症状，请及时就医。」
  —— 这一条是硬边界：我们做的是注意力转移/放松，不做镇痛疗效宣称。

### 2.4 波次与颜色

能量仓中心：**3 圈 → 5 圈**，颜色由玫瑰 → 橙 → 金 → 青 → 蓝逐层外展，周期 3.6 s、依次错开 0.7 s；
中心再叠一层径向光晕呼吸（`vglow`）。

### 2.5 文案清理

首页说明改为「你在任何地方按下「意念注入」，都会计入这个共享的仓；」；
音疗入口副标题、我的入口副标题、服务端 `note` 里残留的「只增不减 / 永久保留」全部改掉
（服务端 note 现为「记录保留，使用能量时会从共享仓扣减」）。

## 五、未验证 / 风险

1. **共享能量会被用成负数吗**：指数是 `10000 + 贡献 − 消耗`，只要基数 10000 远大于消耗就不会为负；
   目前没有"余额不足则拒绝使用"的判断（师父未要求，且体验上不必卡）。若以后参与量很大，建议加下限保护。
2. **「舒缓不适」没有做效果度量**：不做前后疼痛评分（避免被理解为疗效证据），只记录场景与部位。
3. 线上只验证了单次开启/结束与 2 次上限，**15 分钟自动收尾未在线上真跑**（本地已验）。
4. 波次是纯 CSS 动画，低端机是否掉帧未测。
5. 旧数据：`vault_session` 里 120 分钟时代的会话仍保留（只增不删）；新规则只影响新会话。
