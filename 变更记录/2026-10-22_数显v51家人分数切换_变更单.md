# 变更单 · 数显 v52「我 / 家人」切换（家人档案 + 能量图两处）

> 变更 id：`2026-10-22-数显v52-家人分数切换`（初版按 v51 写，追加能量图后整体发 v52）
> 师父原话①：「元神的用户中心，家人的健康打分情况没有切换显示」
> 师父原话②（附「人类能量粒子流变图」截图）：「这里增加：我/家人 的切换查看」
> 现场核定（2026-10-22 14:4x）：家人卡片**本来就有分数**（`/family` 返回每人 `index.score`），
> 缺的是**切换入口**；能量图则连家人的**通道读数**都没有（`index.channels` 只在本人 `daily` 里有）。

## 一、做什么

**两处「我 / 家人」切换**（同一套 chip 样式、同一份数据来源）：

1. `shuzi/web/` 家庭健康档案屏（`#screen-family`）在「全家概览」之后新增一张卡：
   - 一排 chip：**我** + 每位家人（顺序＝`GET /family` 的 `members` 顺序）；
   - 点谁，下方大字显示**那一位**的今日健康指数：分数 / 分档（如 `C · 中`）/ 依据原文 / 等级口径。
2. 今日节律屏「人类能量粒子流变图」（`#energyCard`）标题下新增同一排 chip：
   - 点谁，**用那一位的十二通道读数重画这张图**，并在图上方注明「按『X』的出生时空推算 · 非诊断」；
   - **只切这一张图**，不动上面的今日指数与观察等级；家人视图不显示等级（原有口径不变）。
3. 服务端**只新增字段**：`family._index_of()` 的返回里加 `channels`（该生辰的十二通道读数），
   其它字段名与语义一个字不动；前端因此能用同一份 `EF.render` 画图，不写第二份算法。

## 三、可验证的验收标准

1. `#famSwitch` 的 chip 数 = 家人数 + 1，第一个文本为「我」，其余顺序与 `GET /family.members` 的 `nickname` 逐字一致。
2. 点「我」→ `#famFocusScore` 文本 = `Math.round(/v1/rhythm/daily.data.index.score)`。
3. 点某位家人 → `#famFocusScore` = 该成员 `index.score` 取整；`#famFocusBand` 文本含 `index.band` 与 `index.band_name`。
4. 家人视图内**不出现** `L0`~`L4` 字样，且含「基线建立中」；本人视图内出现等级或「基线建立中 n/7」。
5. 切换**不跳屏、不发新请求**：`#screen-family` 仍可见，切换期间 `/family` 请求数 = 0。
6. `console error = 0`；390×844 与 1440×900 均无横向溢出（`scrollWidth <= clientWidth`）。
7. 旧功能不回归：家人卡片上「关怀提醒 / 编辑 / 删除」三键仍在；点「编辑」→ 表单展开且标题为「编辑家人」。
8. 键盘可达：chip 是 `<button role="tab">`，Enter 触发后该 chip `aria-selected="true"`，且**全组只有一个** true。
9. `#energySwitch` 的 chip 数 = 家人数 + 1，首个为「我」，顺序与 `GET /family.members` 一致。
10. 点某位家人 → `#energyWho` 文本含该家人昵称，`#energyBody` 内有 `<svg>`（图确实重画），且 `pageerror = 0`。
11. 点回「我」→ `#energyWho` 隐藏、图仍在（`<svg>` 非空）。
12. `GET /family` 的每位家人 `index.channels` 长度 ≥ 8（服务端只新增，未改既有字段）。
