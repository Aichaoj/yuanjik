## 五、★ 上线过程中的四个真实故障与处置（本次最有价值的部分）

本次上线**触发过 4 次自动回退**（回退机制每次都正确生效、站点全程可用），逐条记下来避免再犯：

### 故障 1 · PowerShell 变量名大小写不敏感

`$H = @{Host='shuzi.yuanjk.cn'}` 随后被 `$h = Invoke-WebRequest …` **覆盖**（PS 里 `$H` 与 `$h` 是同一个变量）→ 之后所有带 `-Headers $H` 的检查全部报「无法绑定参数 Headers」→ 12 项伪失败 → 回退。
**处置**：请求头变量改名 `$HDR`，并在注释里写明这条陷阱。

### 故障 2 · 线上入口是 IIS，不是本服务

**实证**：`IIS_SITE name=yjk-shuzi physicalPath=D:\www\yjk\shuzi\web`。
IIS **从磁盘直接服务 `web/`，只把 `/api/*` 反代到 15041**。
因此 `serve.py` 里的 `/openapi.json` 与 `/docs` 分支**对公网根本不可达**——它们在服务端确实返回 200，但请求到不了服务端。
**处置**：部署时由运行中的服务生成 `web/openapi.json` 静态快照，并把 `docs.html` 复制为 `web/docs/index.html`；`/docs`、`/docs/`、`/docs.html` 三种写法全部 200。

### 故障 3 · 快照生成早于服务就绪 + PS 5.1 读不到非 2xx 响应体

服务重启后固定 `Start-Sleep 12` 就生成快照，若服务尚未监听则得到空文件 → 404 → 回退；
另外 PS 5.1 的 `Invoke-WebRequest` 在非 2xx 时**无法再读响应体**（流已消费），导致 403 检查伪失败。
**处置**：① 改为**轮询 `/api/health` 直到 200**（最多 120s）再生成快照，且生成失败重试 5 次；
② 需要读错误响应体的检查一律改用 `curl.exe` 落盘再读。

### 故障 4 · PowerShell 5.1 把 JSON 当 argv 传给 curl 会吃掉引号

`curl -d $b`（`$b` 是 JSON 字符串）→ 双引号被吞 → 服务端判「不是合法 JSON」→ 400 而非 401/403。
**处置**：把 JSON 先写进文件，用 `--data-binary "@文件"` 传。

### 附带发现 · sink 结果通道会丢回帖

第 3 次上线的回帖**在服务器侧明确 `DONE REPORTED`，但 sink 列表里始终没有对应文件**（同批前两次都有）。
**处置**：增加**持久报告通道**——部署脚本把日志写到 `web/_deploy_open1.txt`，本机直接 `GET https://shuzi.yuanjk.cn/_deploy_open1.txt` 回读；sink 退为备用通道。此后再未丢过。

> ★ 沉淀成一句话：**在上线脚本里，「验证」本身也要按生产标准写**——变量作用域、入口拓扑、时序、编码，任何一处想当然都会把「成功」误判成「失败」（本次 4 次回退全部是误判，不是真实故障）。

## 七、一处口径变更（需师父知悉）

**「错 key → 403」的错误码，由借用段首码改为专用码。**

- 原状：既有 `服务端/app/http.py` 的 `_HTTP_OF_SEGMENT` 规定 **只有 7xxxx 段映射为 HTTP 403**，故交付方先借用了段首码 `70000`（`CONSENT_REQUIRED`，同意语义）——语义不干净。
- 现改为：在 `服务端/app/errors.py` 的 7xxxx 段**纯追加** `API_KEY_INVALID = 70005` 与 `API_KEY_REVOKED = 70006`（连带两条 `_MESSAGES`）。
  不改任何既有码值与语义；追加后服务层 104 项测试与开放 API 75 项测试全部重跑通过。
- 线上实测：错 key → **403 / code=70005 / reason=invalid_api_key**；停用凭据 → **403 / code=70006 / reason=api_key_revoked**。

**另一处**：合规四件套（`disclaimer` / `ai_generated` / `rule_version` / `param_hash`）放在响应 **`data` 内**（沿用全站 `code/message/data/trace_id` 结构），不在顶层；已在 `/openapi.json` 的 schema 与 `/docs` 写明。若对外要求顶层字段，需再定一次。
