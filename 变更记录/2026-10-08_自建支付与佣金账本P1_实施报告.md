- `sub_plan(plan_id, name, days, price_cents, active)` —— 种子月卡 9900 / 季卡 19900 / 年卡 199000（**整数分**，价格留配置）
- `sub_order(order_no PK, member_id, plan_id, amount_cents, paid_cents, status, channel, paid_at, refund_cents, created_at, idempotency_key UNIQUE)`
- `commission_ledger(id PK, order_no, referrer_member_id, referee_member_id, base_cents, rate_bp, amount_cents, status, reversed_cents, settled_at, created_at, UNIQUE(order_no, referrer_member_id))`
- `pay_callback_log(...)`（变更单许可的"需要的话"新增表）：回调留痕 + **报文级幂等**
  ——**验签通过的同一份报文只留一行**（部分唯一索引），重放只在原行记 `replayed=1 / replay_count+1`。

### 2.3 佣金规则（严格照师父口径）

- 基数 = `paid_cents`（**实付**，不是标价、不是毛利）；比例 = `COMMISSION_RATE_BP = 3000`（30%）
- 计算：`(base_cents * 3000 + 5000) // 10000`（**整数**四舍五入到分，无浮点、可复算）
- 每次**支付成功**（含**续费**）都计佣；**同订单号幂等**（`UNIQUE(order_no, referrer_member_id)` + `INSERT OR IGNORE`）
- **退款冲正**：整单退 → `status='reversed'`、`reversed_cents = amount_cents`；部分退 → `reversed_cents = 按已退金额同比例`
- **自推自买** → 不计佣（金额 0）+ 落 `status='manual_review'` 人工复核行（基数照记，便于复核）
- **无推荐人** → 不计佣、**不报错**（静默跳过，只留审计行）
- 结算：`pending → settled`（T+7，读路径惰性结转）；**提现 P1 不开放**（`withdraw_enabled=false` + 说明）

## 10 验证过程中被测试抓出并已修掉的两个真问题（留痕）

1. **回调留痕撞唯一索引**：重放时又 INSERT 一行 → `UNIQUE constraint failed: pay_callback_log.channel, body_sha256`（HTTP 500）。
   → 改为「**验签通过的同一报文只留一行**，重放只在原行累加 `replay_count`」，并把唯一性交给
   **部分唯一索引**（`WHERE signature_ok = 1`，避免"先拿错签名探路"污染去重表）。
2. **未提交事务挂住写锁**：上面那次失败留下一个未提交事务，后续请求 15 秒后全部
   `database is locked`（多线程各自持连接 ⇒ 互相阻塞）。
   → `_log_callback` 内 `try/except sqlite3.Error: rollback()`，并在 `handle_dynamic` 的兜底分支
   显式回滚当前线程连接，**绝不留半截事务**。
