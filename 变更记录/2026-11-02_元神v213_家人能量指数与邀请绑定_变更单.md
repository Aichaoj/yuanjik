## 一、数据模型

```sql
-- ① 家庭档案增加绑定关系（可空 = 未绑定）
ALTER TABLE family_member ADD COLUMN linked_member_id TEXT NOT NULL DEFAULT '';
ALTER TABLE family_member ADD COLUMN linked_at TEXT NOT NULL DEFAULT '';

-- ② 邀请码（6 位数字，24h，一码一人）
CREATE TABLE IF NOT EXISTS family_invite (
  code        TEXT PRIMARY KEY,          -- 6 位数字
  family_id   TEXT NOT NULL,
  owner_id    TEXT NOT NULL,             -- 创建人 member_id
  created_at  TEXT NOT NULL,
  expires_at  REAL NOT NULL,             -- epoch 秒
  used_by     TEXT NOT NULL DEFAULT '',  -- 接受方 member_id
  used_at     TEXT NOT NULL DEFAULT '',
  revoked     INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_finvite_owner ON family_invite(owner_id, created_at);
```

## 二、接口（全部需登录；路径新增，不动既有契约）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/family/invite/create` | `{family_id}` → `{code, expires_in, family}`；同一家人已有未过期码则复用 |
| POST | `/v1/family/invite/accept` | `{code}` → `{family_id, linked:true}`；**由家人本人在自己手机上提交** |
| GET  | `/v1/family/invite/status` | `{family_id}` → `{linked_member_id, linked_at, code, expires_at, used_by_masked}` |
| GET  | `/v1/family/members/{id}/energy` | 已绑定 → 该家人的真实能量指数（复用 `vault` 计算）；未绑定 → `{linked:false, index:null}` |

**绑定规则**
- 一码一人：`used_by` 非空即失效；
- 过期 / 撤销 / 已被用 → 400 可读提示；
- 不能绑自己（`owner_id == 当前 member` → 拒绝）；
- 同一家人重复绑定 → 拒绝并提示"该家人已绑定"；
- 接受方账号若已绑过别的家庭档案 → 拒绝（一人只绑一条家人记录）。

## 三、能量指数口径

| 查看对象 | 显示 |
|---|---|
| 自己 | `/v1/vault/energy`（既有） |
| 家人（已绑定） | 用 `linked_member_id` 调同一套 `_energy_parts`（**只读**，不改对方的流水与额度） |
| 家人（未绑定） | `—` + 一行「邀请家人建立能量档案」 |

> 隐私：绑定后**只读**对方的能量指数与健康指数，不读对方的短信/通话/情绪记录；对方可随时解绑。
