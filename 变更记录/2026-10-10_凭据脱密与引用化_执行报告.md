## 三、机制：文件里只剩「怎么取」，不再有「取什么」

**新文件 `_zfcred.py`（不含任何真值，已在仓库）**：

```python
from _zfcred import cred
PWD = cred("SHUZI_ADMIN_PWD", "nexus.redcode.basic")        # 字符串
KEY = cred("SHUZI_SM4_KEY", "shuzi.sm4.key").encode()        # 字节
```

- **取值顺序**：① 环境变量（`zfsafe exec --env SHUZI_SM4_KEY=vault:shuzi.sm4.key -- python x.py`，推荐）
  → ② 本机保险柜兜底（现场解析，真值只在本进程内存，不落盘、不上屏、不进命令行）。
- **为什么一定要有兜底**：只认环境变量的话，日常 `python _tool_x.py` 会因"少个变量"直接报错，
  久了必然有人图省事把明文抄回去。**兜底让它照旧能用，明文就没有存在的理由。**
- **取不到就明确失败**（抛 `CredMissing` 并打出可直接照抄的命令）——**绝不静默返回空串**，
  否则"密钥没取到"会伪装成"跑通了但结果全错"。

## 五、★ 本轮抓到的真 bug（**如果没写这条测试，8 个脚本会静默发错口令**）

那 8 个文件的 JS 片段裹在 **Python 三引号** `"""…"""` 里。我第一版把 `'<口令>'` 换成
`'" + _ZF_PWD + "'` —— **三引号里插一个 `"` 根本不会断开字符串**（只有连续三个 `"` 才结束），
结果 JS 收到的是字面量 `" + _ZF_PWD + "`，**口令变成一串乱码**。
而 `py_compile` **照样通过**、明文**也确实归零了** —— 表面全绿。

**抓住它的是 `_verify_cred\test_credref.py` 的 T3**：把 `pg.evaluate("""…""")` 的参数
**按 AST 还原成真实 JS 文本**，再断言里面是否真的出现 `password:'<真值>'`。
一跑就红：`插值位置不对`。
**正确形态**是把三引号本身断开：`password:'""" + _ZF_PWD + """'`。
→ 立即用 `_bak-credref-*` **整体回滚 42 个文件**，修工具，重做，再验 —— 这次 6/6 全绿。

**沉淀的判据**：凡"把值嵌进另一种语言的字面量"这类改写，
**必须能把最终文本还原出来断言**（AST 还原 / 真跑一次 / 抓包），
`语法通过 + 明文归零` **两盏绿灯都证明不了它是对的**。
