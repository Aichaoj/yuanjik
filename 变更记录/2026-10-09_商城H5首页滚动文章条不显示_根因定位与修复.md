# 变更记录 · 商城 H5 首页「滚动文章条」不显示 —— 根因定位与修复（2026-10-09）

> 师父提问：「后台增加了滚动显示的文章，怎么前台没有显示」
> 等级：**L2（线上前端注入补丁 + 根因定位）**　｜　通道：静默通道（零键盘）
> 站点：`h5.yuanjk.cn` / `yuanjk.cn/h5`（同一站点，物理根 `D:\www\yjk\web\h5`）

---

## 一、结论（一句话）

**不是后台的问题，也不是接口的问题，是前端 H5 的一个组件没注册。**

首页那条滚动通知用的是 uni-ui 组件 `<uni-notice-bar>`，但**该组件在本次 H5 构建里没有被注册**，Vue 就把它当成「浏览器不认识的未知标签」直接输出成一个**空元素** —— 所以后台加了文章、接口也返回了，页面上却是**一条空白**。

**已修复并上线**：用前端注入补丁（不重新编译）把该标签自己渲染成**无缝横向滚动文字**，现在首页能看到「AI数显-元神上线　　　内测通知」在滚动。

## 二、证据链（逐环节排除）

| # | 环节 | 实测结果 | 判定 |
|---|---|---|---|
| 1 | 后台有没有这篇文章 | `T_Article` **2 行**：`AI数显-元神上线`（Sort=2，创建 2026-10-09 22:38:07）、`内测通知`（Sort=0），**`IsDelete` 都是 0（均已发布）** | ✅ 正常 |
| 2 | 接口有没有给前台 | `GET https://api.yuanjk.cn/api/article/homeList` → **200，返回 2 条** | ✅ 正常 |
| 3 | 前台有没有调接口 | 真浏览器抓包：首页确实发了 `GET /api/article/homeList` | ✅ 正常 |
| 4 | 前台有没有拿到文本 | 组件 props `itemNew` 有值 → `noticeText` 被赋值 | ✅ 正常 |
| 5 | **渲染层** | DOM 实测：`<uni-notice-bar data-v-6101e502 scrollable="true" text="内测通知" class="h5-bar"></uni-notice-bar>` —— **元素存在、`text` 属性有值，但元素内部完全为空、无任何子节点、`.uni-notice-bar__content-text` 不存在** | ❌ **断在这里** |

**第 5 条就是根因**：`<uni-notice-bar>` 是 **uni-ui 扩展组件**（不是 uni-app 内置的 `uni-view/uni-image` 那类），需要 easycom 或显式 import 注册。编译产物里它被当作原生元素 `i("uni-notice-bar", {...})` 输出，而不是组件引用。

**为什么没注册**（源码侧）：
- 组件源码**存在**：`YJK-Uniapp\uni_modules\uni-notice-bar\components\uni-notice-bar\uni-notice-bar.vue`（11,164 B）
- 但 `YJK-Uniapp\pages.json` **没有 `easycom` 配置**，本次构建也就没自动注册它
- 使用处 `pages/index/components/notification/index.vue` 里是**直接写标签**（`<uni-notice-bar ... />`），没有 import

**影响面**：全项目搜索确认，**只有首页通知条这一处**用到 `uni-notice-bar` —— 其它页面不受影响。

## 三、修复（前端注入补丁，零编译）

**落点**（H5 站点根，已确认）：

```
D:\www\yjk\web\h5\index.html          ← 注入一行 <script>
D:\www\yjk\web\h5\static\js\yjk-notice-fix.js   ← 新增补丁（4,640 B 起）
```

- 该 index.html **本来就有我方注入的先例**（`<style id="yjk-login-captcha-off">`、`<script src="/static/js/shuzi-entry.js?v=20261008b">`），所以走同一套通道，风险已知、可回滚。
- 补丁做什么：找到每个 `<uni-notice-bar text="...">`，读取 `text` 属性，自己渲染成一个 `<span class="yjk-notice-inner">` 并按容器宽度**重复铺满**，用 CSS 动画 `translateX(0 → -一份宽度)` 做**无缝横向滚动**。
  - 文本变化（后台又加文章）→ 轮询里重建
  - 无文本 → 不占位（与「后台没文章」的空状态一致）
  - 只认 `uni-notice-bar` 这一个标签，不碰接口、不碰数据、不碰其它组件

## 六、根治建议（可选，需重新编译 H5）

补丁解决的是**显示**；源码层面的根因是 easycom 没注册。要根治，二选一后**重新编译并部署 H5**：

- **A. 显式注册**（改动最小）：在 `YJK-Uniapp\pages\index\components\notification\index.vue` 里
  ```js
  import uniNoticeBar from '@/uni_modules/uni-notice-bar/components/uni-notice-bar/uni-notice-bar.vue'
  export default { components: { uniNoticeBar }, /* ... */ }
  ```
- **B. 打开 easycom 自动扫描**：给 `YJK-Uniapp\pages.json` 加
  ```json
  "easycom": { "autoscan": true,
               "custom": { "^uni-(.*)": "@/uni_modules/uni-$1/components/uni-$1/uni-$1.vue" } }
  ```

**在重编译之前，请不要删补丁**（删了首页通知条又会变回空白）。

## 七、后台侧的使用说明（给师父）

- 文章**加完要点列表右侧的「发布」**：后台列表用 `IsDelete` 兼作状态位 —— `IsDelete=1` 时操作列显示的是「**发布**」按钮（未发布），`IsDelete=0` 才认为已发布、才会进首页接口。
- **控制首页顺序用「排序」**：数字大的排前面（本次 `Sort=2` 的「AI数显-元神上线」排在 `Sort=0` 的「内测通知」前面）。
- 首页滚动条会把**所有已发布文章**的标题拼成一条滚动文本（标题之间自动留间隔）。
- 文章的**分类（ArticleCategoryId）**目前两篇都是 0，不参与筛选。
