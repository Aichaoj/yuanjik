## 二、为什么这么做（先查清楚，再动手）

底部导航**不是页面自绘组件，是 uni-app 原生 tabBar**。实测（真浏览器 + 主包反查，2026-10-10）：

| 事实 | 证据 |
|---|---|
| 配置在 `window.__uniConfig.tabBar.list`（4 项） | 主包 `index.yjkb1.js` 偏移 577997 处：`tabBar:{color:"#282828",selectedColor:"#ff3366",list:[…]}` |
| 该配置**是响应式的** | `__uniConfig.tabBar=Vue.observable(…)`（chunk-vendors 偏移 260197） |
| 底栏组件对 `list` 有 deep watcher ⇒ push 即重渲染 | 组件脚本：`watch:{list:{deep:!0,handler(){this._initVisibleList();this.setSelectedIndex()}}}` |
| 点击会**真跳转** | `_switchTab`：`uni.switchTab({from:"tabBar",url:"/"+pagePath,detail:u})` |
| 组件按 `visible!==false` 过滤，图标取自 `getIconPath()` | 组件模板 `t._l(t.visibleList,…)` / `_initVisibleList()` |

⇒ **做法**：只往配置数组 `splice` 一项（框架自己渲染，等分布局/图标/选中色全原生），**不做 DOM 硬插**
（DOM 硬插会与 Vue 的 keyed diff 打架）。「暂不做链接」用**占位路由 + document 捕获阶段拦截**
（`preventDefault + stopPropagation` ⇒ Vue 挂在元素上的冒泡监听收不到事件），拦截后给一句 toast。

> 反例记录（避免后人走弯路）：`购物车/我的` 等文案在主包里搜不到属正常（文案在 `__uniConfig` 里）；
> 而 `5-00x.png` 这类**不存在的静态文件**在本站会**被 SPA 回退成 index.html 并返回 HTTP 200** ——
> 所以「图标在不在」**不能只看状态码**，必须校验**字节数与 PNG 魔数**（本次即如此设卡）。

## 七、未验证 / 风险（如实）

1. **登录后的真实 tab 页未验**：本机无商城 C 端测试账号（登录走短信验证码），故 ①④ 的复验是在
   登录页把隐藏的底栏打开后做的。渲染由**同一个组件、同一份配置**驱动，风险低；但「首页/我的 上
   的选中态高亮位置」**未经真实登录态目视确认**，请师父在手机上瞄一眼。
2. **提示文案**「涅槃道预约：功能即将开放」是我加的（"暂不做链接"不等于"点了没反应"）。不想要就把
   补丁里 `TOAST_ON = true` 改成 `false` 重投一次即可。
3. **占位路由** `pages/nie-pan/booking/index` 站上**不存在**——这是"不跳转"的第一道保险（第二道是
   捕获拦截）。将来要做真页面时，把 `PAGE_PATH` 换成真实路由并去掉拦截即可。
4. **5 项布局**：390px 宽下每项 78px、文字 50px 单行 → 不挤；极窄屏（<320px）未测。

- **哪条铁律救了命**：**铁律十二（受令先停、先查旧错）**——先停 5 秒去反查主包，才发现"点击会真跳转"，
