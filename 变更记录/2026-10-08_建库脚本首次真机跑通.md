## 五、修了什么（两处，均为首次真机执行才暴露）

### 修复 1 —— `schema_v1.sql:699`（原行号）

```
ERROR: functions in index expression must be marked IMMUTABLE
```

原写法：

```sql
CREATE INDEX idx_symptom_name_trgm ON tcm.symptom
  USING gin ((name_zh || ' ' || array_to_string(synonyms,' ')) gin_trgm_ops);
```

**原因**：`array_to_string(anyarray, text)` 在 PostgreSQL 中被标记为 **STABLE**（内部会调用元素输出函数），而**索引表达式只接受 IMMUTABLE 函数**。对 `text[] / text` 而言该拼接实际是确定性的。

**处理**：新增显式声明 `IMMUTABLE` 的 SQL 包装函数 `tcm.symptom_search_text(text, text[])`，索引用它——**保持「名称 + 别名」单索引模糊检索的原设计不变**，而不是拆成两个索引或删掉该索引。

### 修复 2 —— 脱敏视图两处（原 `:3308`、`:3322`）

```
ERROR: function convert_from(text, unknown) does not exist
ERROR: relation "core.v_account_masked" does not exist   （连锁）
```

原写法：

```sql
audit.mask_phone(convert_from(pgp_sym_decrypt(a.phone_enc, current_setting('app.dek', true)), 'UTF8'))
```

**原因**：`pgp_sym_decrypt(bytea, text)` 的**返回类型本身就是 text**（列 `phone_enc`/`name_enc` 均为 `bytea`，正合其入参），再套 `convert_from(text, 'UTF8')` 属多此一举且**签名不匹配**（`convert_from` 要求 `bytea` 入参）。视图建不起来，又连锁导致 `:3528` 的授权语句报 `relation does not exist`。

**处理**：直接取 `pgp_sym_decrypt` 的返回值；并在注释里写明「仅当密文列确为 bytea 且要原始字节时，才应改用 `pgp_sym_decrypt_bytea(...)` 再 `convert_from`」。

> 两处修复均在原地以中文注释注明「2026-10-08 修 · 首次真机执行暴露」及原因，便于代理机构/接手人复核。
