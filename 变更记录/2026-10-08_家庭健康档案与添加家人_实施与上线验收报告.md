## 三、接口（全部要求登录）

| 方法 + 路径 | 说明 |
|---|---|
| `GET /api/v1/family` | 家人列表 + 家庭汇总 + 最近提醒 + 免责声明 |
| `POST /api/v1/family/members` | 添加家人 |
| `POST /api/v1/family/members/update` | 修改（body 带 `family_id`） |
| `DELETE /api/v1/family/members/{family_id}` | 删除（`handle_dynamic`；**不是你的家人一律 404，不泄露存在性**） |
| `POST /api/v1/family/remind` | 关怀提醒（`care/checkin/birthday/custom`；**当日同 kind 幂等**） |
| `GET /api/v1/family/reminders` | 我发出的提醒 |

**四条硬边界（已在代码与服务端逐条落实）**
1. 家人指数与「我」**同一条链路**：内核 `phase_index` → 注入的 `display_normalize`，**不另写第二份公式**；分档用内核 `band_of`（85/70/55）。
2. 家人 `level` **恒为 `null`**，页面只显示「基线建立中 0/7」，**全文不出现 L0–L4**（专利 2 权利要求 6）。A/B/C/D 是时相分档，**不是**观察等级。
3. 家人**不是账号、没有 member_id**，以「录入者 member_id」为属主；本模块**不读不写** `social_*` 任何表 ⇒ 家人昵称/生辰**不可能**出现在 `friends`/`feed`/`ranking`/邀请预览里。
4. 不做诊断、不做医疗表述；随附内核既有免责声明。

## 七、待师父定的一处口径

**家庭席位满时返回 HTTP 402**（复用既有专用码 `SEAT_LIMIT_EXCEEDED = 30003`；既有码表把 3xxxx 段映射为 402「需付费」，`SEAT_LIMIT_EXCEEDED` 本就是该段为「席位上限」预留的码）。
我的判断：**保留 30003** —— 它是系统为"席位"预留的专用码，语义最贴；前端按 message 展示，用户看到的是「家庭席位已满（8 位）：如需继续添加，请先删除一位家人。」
若师父要求统一成 **400**，改 1 行 + 重跑自测即可。

前端 `saveFamMember()` 的本地校验要求经纬度非空（`famCity` 选城市会自动回填），于是**提交被本地校验拦下**，
