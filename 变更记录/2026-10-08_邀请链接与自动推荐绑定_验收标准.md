# 变更单 · 邀请链接与自动推荐绑定（v6）

> 变更 id：`2026-10-08-邀请链接与自动推荐绑定`
> 等级：**L2（新增接口/数据）＋ L3（站点已上线）**
> 师父指令原文：「好友圈的复制邀请码需要带注册链接并自动作为推荐人才行，不然新用户不知道怎么加好友。」

## 一、意图与要解决的问题（师父的原话就是问题陈述）
现在只给一个 8 位邀请码，新用户拿到后**不知道去哪输入、怎么加**。改为：
**复制的是「带邀请码的注册链接」**，朋友点开链接 → 注册（建档）时**自动绑定推荐人**，并**自动成为好友**，无需再手工输码。

## 二、两个关系必须分清（这也是佣金的地基）
| 关系 | 含义 | 绑定方式 | 可否更改 |
|---|---|---|---|
| **推荐关系 referral** | 谁推荐的谁（佣金归属，用于师父要的 30% 分成） | 点链接即绑，**自动、即时** | **一次性、不可改绑**（除后台人工并留痕） |
| **好友关系 friend** | 好友圈可见性 | 点链接即**自动 accepted**（对方主动分享链接即视为同意） | 可解除 |

> 必须先有 referral 表：**在佣金系统上线前注册的用户，若现在不记归因，将来无法补**。

## 三、接口（新增/扩展）

```
GET  /api/v1/me/referral            → {invite_code, invite_url:"https://shuzi.yuanjk.cn/?invite=<code>",
                                        referred_by: null | {nickname, bound_at}}
POST /api/v1/friends/invite         → 扩展：{invite_code, auto_accept?:true}
                                       auto_accept=true 时：建立 accepted 好友关系 + 绑定 referral（一次性）
```
规则：
- `referral.referee_member_id` **唯一**（一个被推荐人只有一条）；已绑定则**不再改绑**（重复调用返回已绑定的推荐人，不报错）
- **不可自荐**（自己用自己的码）→ 拒绝（沿用既有 `30005 INVITE_SELF_NOT_ALLOWED`）
- 绑定失败**不得影响注册主流程**（前端静默降级）

## 四、数据（沿用 state.db）
```
referral(referee_member_id TEXT PRIMARY KEY,      -- 被推荐人（唯一）
         referrer_member_id TEXT NOT NULL,        -- 推荐人
         invite_code TEXT NOT NULL,
         bound_at TEXT NOT NULL,
         source TEXT)                             -- link / manual
```

## 五、验收标准（可验证，逐条自检）
| # | 验收标准 |
|---|---|
| 1 | `GET /api/v1/me/referral` 返回 `invite_url`，且**逐字包含** `https://shuzi.yuanjk.cn/?invite=<invite_code>` |
| 2 | B 用 A 的 `invite_code` 调 `POST /friends/invite {auto_accept:true}` → 双方 `GET /friends` 互为 `accepted`；**无需 A 再确认** |
| 3 | 同一调用后 `referral` 表新增且仅新增 **1 行**：`referee=B, referrer=A` |
| 4 | B 再次调用（或改用 C 的码）→ referral **仍指向 A**（不可改绑），返回体里 `referred_by` 仍是 A |
| 5 | A 用自己的码 → 拒绝（`30005`），且不产生 referral 行 |
| 6 | 前端「复制邀请链接」复制出来的文本**含 `?invite=` 与 8 位码**；按钮文案为「复制邀请链接」 |
| 7 | **浏览器实测**：B 打开 `https://shuzi.yuanjk.cn/?invite=<A的码>` → 建档 → 自动绑定：B 的好友列表含 A、A 的好友列表含 B（线上或本地真后端均可，须贴证据） |
| 8 | 链接参数在**重复访问/刷新**时不重复绑定、不报错（幂等） |
| 9 | 绑定失败（如码无效）**不阻塞注册**：用户仍能建档、看到指数卡，仅提示"邀请码无效" |
| 10 | 既有测试零回归：社交 51 项、内核 335、服务端 104 全过 |
