## 一、三件事（A / B / C）

### A. 器官层（示意）

- 立体人体新增「器官（示意）」层：**11 个点位**——心、左/右肺、肝、胆、脾、胃、左/右肾、肠、膀胱；
- 切到器官层时躯干调为半透明（opacity 0.26），器官小球显露；点选发光；仍可拖动旋转；
- 映射沿用五行—五音：心→徵、肺→商、肝/胆→角、脾/胃→宫、肾/膀胱→羽、肠→商；
- **页面明写**：器官位置为示意，不是解剖精确位置，不用于定位诊断。
  （真正器官级需要专业模型 + 医学校对，这一版没有宣称做到。）

### B. 呼吸节拍音

- `music.js` 新增 `cue(kind)`：吸气 528 Hz / 停 396 Hz / 呼 264 Hz（呼气下行）/ 木鱼 660 Hz 三角波，短包络、极轻；
- 呼吸页新增选择：**节拍音：关 / 轻 / 木鱼**（默认轻）；阶段切换即响一记；
- 关闭后不再触发（自测里用计数验证：开启时计数增长、关闭后不再增长）。

### C. 曲库管理（后台）

- 新模块 `server/musiclib.py`：表 `music_track`，启动时用现有 `web/music.json` **播种 6 条**，之后以库为准；
- 接口：
  - `GET /api/v1/music`（**公开**）——只回上架曲目、字段裁剪（无 enabled/sort）
  - `GET /api/v1/admin/music` / `POST …/save` / `…/toggle` / `…/delete`（**后台令牌**，复用 `/v1/admin/login`，不新造鉴权）
- 前端「音疗 → 佛音」改为**先走后端曲库**，取不到再退回静态 `music.json`；
- 新增后台页 `web/admin/music.html`：登录 → 列表（排序/标题/文件/授权/状态）→ 新增/编辑/上架下架/删除；
  **删除只删记录、不删音频文件**（避免误删原件）。

## 四、未验证 / 风险

1. 器官位置**未经医学审校**（示意）；若要做器官级，需要专业模型与医生校对。
2. 节拍音**未人耳验收**（只验证触发与计数）。
3. 曲库管理**没有做权限分级**（后台令牌是"全权"）；多管理员/操作审计只到 `admin_audit` 的一条事件。
4. 曲目仍以"文件路径"引用，**没有上传接口**——音频文件仍由运维放到 `web/music/`；若要后台上传，需另开上传通道（且 >2 MB 的通道限制要先解决）。
5. 后台路由用 `auth_required=False` + 自带令牌校验（与既有 admin 一致），未做额外的 IP 白名单。

## 五、教训

- 既有 admin 路由是 `auth_required=False` + 自己校验令牌；**新模块沿用同一手法**，否则会被全局鉴权按 C 端令牌拦掉（本次踩了一次，401 排查 10 分钟）。
- 富媒体版本继续坚持**逐文件传输**（单文件 >2 MB 会被上传接口拒）。
