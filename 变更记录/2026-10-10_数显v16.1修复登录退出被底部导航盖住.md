# 变更记录 · 数显 v16.1：修「登录 / 退出被盖住」（底部导航压住抽屉）

> 师父反馈（2026-10-10）：「**登录，退出都被盖住了**」（附截图：退出确认抽屉底部被「今日节律」tab 盖住）
> 等级：**L2（前端层次修复）**　｜　通道：静默通道（零键盘）
> **性质**：**我自己在 v15 引入的缺陷** —— 加底部导航时把 `.tabbar` 定到 `z-index: 60`，
> 而抽屉 `.sheet` 一直是 `50`，于是底部导航压在抽屉上面，把抽屉底部的按钮整条盖住。

---

## 一、结论

**已修复、已自测（真浏览器 12/12）、已上线、已公网复验，未回退。**

- 抽屉打开时**自动隐藏底部导航**（`body.sheet-open .tabbar { display: none }`，由既有的 `syncSheets()` 一处驱动，**所有抽屉**都受益）；
- 同时把层次一次理清：`.sheet` `50 → 80`（**必须高于** `.tabbar` 的 60），`.toast` `60 → 95`，`.busy` `70 → 100`。

---

## 二、根因

| 层 | 修复前 z-index | 修复后 |
|---|---|---|
| `.sheet-backdrop` | 40 | 40 |
| **`.tabbar`**（v15 新增） | **60** | 60（不变） |
| **`.sheet`**（抽屉） | **50** ← **比 tabbar 低** | **80** |
| `.toast` | 60 | 95 |
| `.busy` | 70 | 100 |

`#authSheet`（登录/注册/找回/退出面板）与 `#confirmSheet`（二次确认）都是 `.sheet`，
**底部那排按钮（登录、退出登录、确定、取消）正好落在 tabbar 覆盖区**，于是被整条盖住。

---

## 三、修法（两层保险）

**① 结构层**：抽屉是模态，底部导航本就不该压在它上面。
`syncSheets()`（抽屉管理的**唯一**汇总点）在任一抽屉打开时给 `body` 打 `.sheet-open`：

```js
document.body.classList.toggle('sheet-open', any);   // any = 有任一抽屉打开
```
```css
body.sheet-open .tabbar { display: none !important; }
```

**② 层次层**：即便将来有人漏掉 `sheet-open`，`z-index` 也保证抽屉在上。

**交付物**

| 文件 | 改动 |
|---|---|
| `shuzi\web\app.js` | `syncSheets()` 增加 `body.classList.toggle('sheet-open', any)`（3 行） |
| `shuzi\web\style.css` | `.sheet` z-index `50→80`、`.toast` `60→95`、`.busy` `70→100`；新增 `body.sheet-open .tabbar { display:none !important }` |
| `shuzi\_verify_v16\test_sheet_overlap.py` | 真浏览器 **12 项**（遮挡判据见下） |

## 五、教训（已写进技能）

**加了 `position: fixed` 的全局组件（底部导航 / 悬浮按钮 / 提示条）之后，必须回头核对整套 z-index 层次**，
尤其是**模态（抽屉/弹层）必须高于它**。本轮就是只想着"底部导航要盖住页面内容"，
忘了**它也会盖住模态的底部按钮区**——而登录/退出/确定/取消这些按钮恰好都在那儿。

**更稳的做法**：模态打开时**把全局固定组件藏起来**（不需要它），
而不是指望"层次调对了就行"（层次能调对，但不能防止将来有人再加一层）。
