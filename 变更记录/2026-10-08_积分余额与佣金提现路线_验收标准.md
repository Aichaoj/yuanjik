# 变更单 · 积分余额（测试期）与佣金提现路线（v8）

> 等级：**L2（新增接口/数据）＋ L3（站点已上线）**
> 师父裁决（2026-10-08）：「先测试积分余额即可，不用真钱，佣金提现后期接通银联分账后再开通。」

---

## 一、裁决落地（两条）

| # | 裁决 | 落地含义 |
|---|---|---|
| 1 | **测试期用积分余额，不用真钱** | 订阅用**积分支付**（`channel=points`）：下单即扣积分 → 订单 `paid` → **佣金按"实付积分 × 30%"计** → 退款**返还积分**并**冲正佣金**。**不接任何真实支付通道、不出网** |
| 2 | **佣金提现后期接通银联分账再开** | **本期不做提现**（按钮置灰 + 说明"待银联分账通道开通"）；P3 走**银联分账**（持牌机构分账，从根上避免"二清"：我方**只记账、不代收代付、不沉淀资金**） |

> 附带好处：测试期完全避开资金合规与税务风险，但把**订单→佣金→退款冲正**的账务逻辑全部跑真（换成真通道时只换 `channel`，账本口径不变）。

## 二、接口（新增）

```
GET  /api/v1/points/balance             我的积分（余额/累计获得/累计消耗）
GET  /api/v1/points/ledger?page=        积分明细（分页）
POST /api/v1/subscribe/order            扩展：{plan_id, pay_with:"points"}  ← 用积分支付
POST /api/v1/pay/callback/points        积分支付回调（内部即时结算，仍走同一回调链路与幂等）
GET  /api/v1/me/commission              既有：收益（**单位说明改为"积分"**，口径 basis='paid_points'）
POST /api/v1/admin/points/grant         后台发放积分（管理令牌鉴权；测试期给师父/测试账号充值）
```

## 三、数据（沿用 state.db）
```
points_account(member_id PRIMARY KEY, balance, earned_total, spent_total, updated_at)
points_ledger(id PK, member_id, delta, reason, ref_order_no, created_at)
```
- 积分**只用整数**；`1 积分 = 1 分`（与既有 `*_cents` 同量纲，便于日后切真钱时口径一致）
- 佣金仍写既有 `commission_ledger`，`base_cents` 记录**实付积分数**，`rate_bp=3000`

## 四、验收标准（可验证）
| # | 标准 |
|---|---|
| 1 | 新用户积分余额 0；`POST /subscribe/order{pay_with:'points'}` 余额不足 → 可读业务码拒绝（**不开单或订单 `unpaid`**），不产生佣金 |
| 2 | 后台发放 20000 积分 → 余额 20000，明细 +1 行 |
| 3 | 用积分买季卡（19900）→ 余额 **100**、订单 `paid`、`channel=points`、**佣金 5970**、积分明细再 +1 行（消耗） |
| 4 | **续费**再买一次 → 余额不足被拒（100 < 19900）；再发 20000 → 可买，**第二条佣金 5970**（不合并） |
| 5 | 退款 19900 → 积分**返还** 19900、佣金 `reversed`、余额与明细同步 |
| 6 | 幂等：同 `Idempotency-Key` 重复下单只扣一次积分、只产生一张订单 |
| 7 | 自推自买不计佣（沿用 P1 规则），但积分照扣（订单有效） |
| 8 | 提现接口**不存在或明确拒绝**且文案含"待银联分账通道开通"（本期不开放） |
| 9 | 前端：订阅页可用积分购买；「我的积分」「我的推广收益（积分）」可见明细；提现按钮置灰并有说明 |
