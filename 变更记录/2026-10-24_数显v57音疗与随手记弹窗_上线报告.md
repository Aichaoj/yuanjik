## 二、做了什么

### 2.1 音疗页（新 tab）

| 区块 | 内容 | 音源 |
|---|---|---|
| 今天建议听 | 按 `/rhythm/daily` 的 `focus`（相对你自己基线偏虚的通道）映射五音：肝/胆→角、心/小肠→徵、脾/胃→宫、肺/大肠→商、肾/膀胱→羽；无基线时按当前时段给一个；可「换一个」 | 本地合成 |
| 五音 | 宫 261.63 / 商 293.66 / 角 329.63 / 徵 392.00 / 羽 220.00 Hz，基音 + 两个泛音 + 0.08 Hz 呼吸起伏 | Web Audio 本地合成 |
| 静心音 | 颂钵（146.8 Hz 四个失谐分音 + 拍频）/ 木鱼（1.6 s 一次短促点击）/ 雨声（白噪音 + 带通） | 本地合成 |
| 佛音 | 读 `music.json` 的 `tracks`，逐条播放；清单为空时显示「素材准备中」，不影响其它功能 | 曲目文件（待素材） |
| 播放条 | 播放/暂停、停止、定时 5/10/15/20/30 分钟（到点自动停）、音量 | — |

- 为什么用本地合成：无版权风险、不占带宽（不塞 mp3），弱网/离线也能听；线上 IIS 没开 gzip（见 v55 报告）。
- 佛音为什么做成清单：真实录音涉及版权与来源，**不硬编进代码**；把文件放进 `web/music/` 并在 `music.json` 登记即出现，
  不改代码、不用重新发版（`music.json` 已随版本上线，当前 `tracks: []`）。
- 合规：页面上写明「只做陪伴，不是治疗」「不能替代就医」；五音只作选择建议。

### 2.2 随手记改弹窗（并修跨设备重复填写）

| 旧（v56） | 新（v57） |
|---|---|
| 卡片里常驻 5×2 个选项 + 睡眠框 + 上报按钮，占屏且每次都要重选 | 卡片只留**一行摘要**：「今日已报：饮食 较好 · 心情 一般 · 睡眠 7h｜点这里修改」 |
| 打开页面时选项全空，换设备要重填 | 进首页先读 `/healthscore/status`，**把上次的记录回填**（饮食/心情/睡眠），点开弹窗即已选好 |
| 上报后卡片原地不动 | 上报成功 → **弹窗自动收起** → 摘要立即变「今日已报」 |

写入口径不变：仍是「先读 → 只覆盖这次填的项 → 再写」，不会抹掉吸烟/运动/血压等其它项（`healthscore_save` 是整行 upsert）。

## 五、未验证项与风险（如实）

1. **佛音一条都没有**：现在只有「素材准备中」的空态。需要师父给可用的音频文件（或授权来源/链接），
   我放进 `web/music/` 并在 `music.json` 登记即可，不需要改代码、不用再发版。
2. **声音没人耳验收**：我验证的是「进入播放态 + AudioContext 正常 + 参数正确」，
   **没有听到声音**（无头浏览器）。音色偏好、音量、耳机下的舒适度，需要师父在真机上点一次。
3. **参照里的「三维人体选部位注入」没做**：那需要 3D 模型与素材，是独立一版；本版只做「按人推荐 + 自选」。
4. **推荐依据的口径**：`focus` 是「相对你自己基线偏虚的通道」，未建立基线时按当前时辰给建议——
   这不是「体质辨识」，只是选择建议，页面上已写明。
5. **未做自动续播/后台播放**：切到别的 tab 音乐会继续（同一 AudioContext），但手机锁屏/切后台是否续播未验。
6. **本地合成在低端安卓上的 CPU 占用**未测（3 个振荡器 + 滤波器，理论上很低）。

## 七、教训与立规

1. **用脚本按行号替换代码块，必须连带检查注释配平**：本次 `/*` 被吃掉，症状是「页面能开、按钮全没反应」，
   表象很像网络问题；以后此类替换后**先跑一次语法注入检查**（`_智能体\diag\find_syntax.py` 已是现成工具）。
2. **静音素材一律做成清单驱动**：音视频这类有版权的资产不写进代码，`json + 目录` 是唯一入口，避免"改一行发一版"。
3. **换设备要重填 ≠ 数据没存**：先分清「服务端没存」还是「前端没回填」。这次是后者（`status` 一直有数据，
   是前端打开时没读、且换账号/换设备时选择器全空）。以后凡"表单"，默认带**回填**。
