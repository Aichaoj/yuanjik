### 2.3 开关（**不是凭据**，可不配）

| 环境变量 | 缺省 | 作用 |
|---|---|---|
| `YJK_PAY_CHANNEL` | `mock` | 选通道：`mock` / `wechat` / `alipay`；**切换与回退就是改它** |

### 2.4 值的两种注入形态

* `*_PATH` 型引用名（`..._APICLIENT_KEY_PATH` / `..._PLATFORM_CERT_PATH` / `..._PRIVATE_KEY_PATH` / `..._PUBLIC_KEY_PATH`）：
  **值就是文件路径**，密钥内容留在文件里，文件 ACL 只给应用池账号。
* 其余引用名（如 `YJK_WXPAY_APIV3_KEY`）：值可直接给，也可给 `<引用名>_FILE=<文件路径>`。

## 四、代码要改哪几处（**最小改动，合计约 8 行**）

### 4.1 `serve.py`：**零改动**
回调分支已经就是 `POST /api/v1/pay/callback/{channel}` → `self.stack.pay.handle_dynamic(...)`，
渠道差异在下面 pay.py 那一层吸收掉，`serve.py` 一行都不用动。
（可选：`/api/health` 里挂一个 `pay_channels.channel_status()`，纯运维便利，不加也能跑。）

### 4.2 `pay.py`：4 处（**当前 931 行的行号，供定位**）

```python
# ① 顶部 import 区，新增 1 行
import pay_channels

# ② 第 100 行，放行真通道（原本只有 'mock'）
SUPPORTED_CHANNELS = ('mock', 'wechat', 'alipay')

# ③ 第 639 行，把「验签 + 取业务载荷」分成两条路（mock 原样不动，真通道走适配层）
        payload = None
        if channel == 'mock':
            ok = verify_signature(channel, headers, raw)          # P1 占位验签位：一个字不改
        else:
            ok, event = pay_channels.get_channel(channel).verify_callback(
                channel, headers, raw)                            # 平台证书/支付宝公钥验签 + 资源解密
            if ok:
                payload = pay_channels.event_to_callback_payload(event)

# ④ 第 651 行（原 `payload = self._parse_body(raw, ctx)`）改成：
        payload = self._parse_body(raw, ctx) if payload is None else payload
```

**为什么必须这样改（而不是只换 `verify_signature`）**：
微信回调的 `raw` 是**加密信封**（`resource.ciphertext`），不是业务 JSON；
`_parse_body()` 读不了它，所以必须让适配层把「验签 + 解密 + 映射」做完，
再把 `{order_no, result, paid_cents, refund_cents}` 交给 P1 的账本逻辑。
**账本口径（实付 × 30%、幂等、退款冲正）一行都不动**，`mock` 分支与 P1 逐字一致。

> 审计留痕：`body_sha256` 仍取**通道原始报文的 sha256**（去重最严格）；
> 适配层事件里另带 `raw_sha256` / `event_id` / `verified_by`，需要时可一并入库。

### 4.3 上线那一天的**唯一一处**出网开关

```python
# pay_channels.py 顶部
ALLOW_REAL_NETWORK = True        # ← 从 False 改成 True（**必须走一次代码评审 + 备份**）
```
同一次改动里补 `_dispatch()` 的函数体（用标准库 `urllib.request`，`timeout` 必填，
真实签名头在 `request['_authorization']`，**它只用于发送，禁止打印/落盘**）。
这两件事**必须同时做**，缺一个都发不出请求 —— 这是刻意设计的双闸门。
