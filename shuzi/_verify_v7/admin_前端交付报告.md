## 二、★ 最重要发现：**契约与实现不一致（已双向兼容）**

任务书给的「冻结契约」是**裸载荷**；线上 `admin_api.py`（同事已落地）实际返回的是
**JSON 信封 + 另一套字段名**。**字段名我一处未改**，而是让前端同时兼容两种形状
（先按变更单字段名取，取不到再按实现字段名取）。

| 项目 | 变更单 §二（任务书） | 线上实现实测 | 前端处理 |
|---|---|---|---|
| 响应外壳 | 裸 JSON | `{code,message,data,trace_id}`，`code=0` 为成功 | 自动解信封，`code≠0` 抛可读错误 |
| 用户列表-建档 | `profile_done` | `profile_completed` + `archive_status`('已建档') | 三级回退 |
| 用户列表-基线 | `baseline_n` → n/7 | `baseline_progress{observation_count,min_observations,text}` | 三级回退，分母取 `min_observations` |
| 运营指标 | `total_users/today_new/profile_rate/checkin_users/social_edges` | `users_total/new_today/archive_rate/checkin_users_total/friend_circle.*` | 逐项别名 |
| 指数分布 | `index_bands{A,B,C,D}` | `index_distribution.items[{code,name,count,pct}]` | 两种都能画，占比和 = 100% |
| 好友圈 | 一次给关系+加油 | `?kind=relations\|cheers` 分开分页 | 新增「好友关系 / 加油记录」分段切换 |
| 封禁对象 | `member_id` | relations 用 `a_member/b_member`、cheers 用 `from_member/to_member` | 取「接受方/被加油方」并写入按钮 title |
| 用户详情 | 平铺 `birth_date` | 嵌套 `birth{birth_date,birth_city}` / `archive{vitals_collected}` | 两种都读 |
| 审计时间 | `created_at` | `at` | 别名 |
| 登录锁定 | 只给锁定时长 | 401 带 `detail.remaining_attempts`；429 带 `detail.remaining_sec` | 界面显示「还可尝试 N 次」/「剩余 N 分钟」 |

> **需师父/同事裁决**：建议以**实现为准**回写变更单 §二（或把实现改成裸载荷）——
> 前端已两边都能跑，不影响上线，但文档与实现不一致会让后续维护踩坑。
