一、路径前缀（务必先读）

本站所有接口都在 /api/v1/... 之下。本文与 /openapi.json 里的路径写成 /v1/...，真实地址请在前面加 /api。 例：文档写 GET /v1/open/shichen，真实地址是 GET https://shuzi.yuanjk.cn/api/v1/open/shichen。

三、鉴权

  • L1：完全免鉴权，任何人可直接调用；按 IP 限流（见下）。
  • L2：请求头 X-API-Key: <凭据>。 未携带 → 20000（HTTP 401）；凭据无效 → 70005、凭据已停用 → 70006（均 HTTP 403）； 合法 → 200。凭据由运营通过 POST /api/v1/admin/api-keys 签发。
  • 运维接口：请求头 Authorization: Bearer <后台令牌>， 令牌由既有后台登录接口 POST /api/v1/admin/login 取得——与 C 端游客令牌完全隔离。

凭据的保管口径（重要）

签发响应里的 api_key 明文只返回一次。服务端库里只保留它的 SHA-256 哈希与前 8 位前缀（前缀仅用于人工核对）， 之后任何接口都取不回明文。请把明文转存到调用方的凭据保管处，不要写进代码仓库、工单或聊天记录。

五、响应结构铁律

成功响应统一为 {code, message, data, trace_id}，其中 data 内强制携带四个字段：

字段含义
disclaimer固定免责声明（与站内其它页面同一份文本）
ai_generated是否由生成式模型产出；本 API 全部为 false，结果是内核确定性推演
rule_version规则版本；规则升级后 param_hash 同步变化
param_hash入参指纹（SHA-256 十六进制）：同输入必得同值，便于第三方复算

另有 lineage（可解释链：规则 ID + 古典出处 + 要点）与 license。

绝不返回病名字段：响应里没有任何病名、诊断或风险概率字段，也不含任何个人健康数据。 本产品不属于医疗器械，不用于疾病的诊断、治疗或预防。
